# Catatan temuan, remediasi, dan retest (bahan Project 3)

Catatan kerja audit teknis untuk penyusunan laporan audit formal oleh ChatGPT. Bukan laporan audit akademik. Setiap klaim merujuk kode, commit, log, atau transaksi. Baseline audit: commit `96b4a08` (salinan ZIP tanpa riwayat Git; riwayat hulu `efa663b` yang dirujuk laporan kekurangan tidak tersedia di checkout ini). Kontrak yang diaudit: `contracts/src/VerifikasiIjazah.sol`.

Label tingkat bukti: **kode** (pembacaan kode), **mock** (tes FHEVM mock/Hardhat lokal), **lokal-nyata** (komponen nyata di mesin lokal, mis. PostgreSQL Docker), **Sepolia** (data on-chain). Kategori keputusan: `TERBUKTI`, `RISIKO_DESAIN`, `INFORMASIONAL`, `TIDAK_TERBUKTI`, `TIDAK_RELEVAN`.

## 1. Threat model (D.1)

| Unsur | Isi |
| --- | --- |
| Aset | (1) Integritas registry institusi/signer dan rekaman kredensial; (2) kerahasiaan atribut privat (tanggal lulus) dan referensi terenkripsi `euint256`; (3) kunci admin, signer institusi, attestor, relayer, result reader; (4) bukti penerbitan off-chain (payload EIP-712 bertanda tangan, profil publik); (5) dokumen unggahan dan hasil OCR; (6) sesi pemeriksa; (7) saldo uji relayer; (8) ketersediaan layanan QR dan pencocokan. |
| Aktor | Pemeriksa anonim; pejabat kampus (signer EOA); administrator platform; backend tepercaya (OCR, attestor, relayer, reader dalam satu batas kepercayaan operasional); penyedia RPC; layanan Zama (relayer, KMS, kontrak ACL/executor); operator penyimpanan (PostgreSQL, blob); penyerang eksternal; signer institusi lain yang berniat jahat. |
| Batas kepercayaan | Browser → API (tidak tepercaya → tepercaya; cookie sesi + CSRF + Origin); API → PostgreSQL/blob (operator tepercaya); wallet kampus → kontrak (tanda tangan pengguna, EIP-712 + tx); backend → kontrak (kunci layanan); aplikasi → RPC (data chain dipercaya dari satu penyedia); aplikasi/browser → Zama relayer/KMS (enkripsi input, dekripsi pengguna); data publik on-chain ↔ data privat off-chain. |
| Skenario penyalahgunaan | Penerbitan atas nama institusi lain; pemalsuan profil publik di database; replay payload/attestation lintas chain/kontrak; perebutan ID kredensial di mempool; penggantian nama institusi saat penerbitan tertunda; kebocoran satu kunci layanan yang memberi kendali penuh; signer lama mendekripsi referensi; penebakan atribut privat melalui pencocokan berulang; pengurasan saldo relayer; spoofing header untuk melewati rate limit; RPC jahat memalsukan state; dokumen jahat terhadap parser OCR; penghapusan admin terakhir. |

Backend yang melihat OCR plaintext tetap pihak tepercaya. FHE melindungi referensi dari pihak tanpa ACL, bukan dari backend yang menyusun input pencocokan.

## 5. Debugging C.2

Kasus nyata yang direproduksi: setelah perubahan kontrak, `hardhat test` melaporkan `reverted with an unrecognized custom error (return data: 0xb41ba2d6)` pada 8–9 tes. Selector didekode dengan ABI (`0xb41ba2d6 => UnauthorizedIssuer()`), sehingga perilaku kontrak benar. Reproduksi deterministik: run yang mengompilasi gagal, run berikutnya (cache) lulus.
